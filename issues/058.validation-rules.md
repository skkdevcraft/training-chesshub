Add or tighten server-side and client-side validation across the application according to the app spec.

## What to build

**Username validation (registration + settings):**

- 3–20 characters
- Allowed characters: letters (a-z, A-Z), numbers (0-9), underscore (_)
- Unique (handled by Identity, but add a check in the registration form for better UX)
- Add `[RegularExpression]` attribute and client-side validation

**Friend request validation (already partially implemented in #040 — verify all rules):**

- Cannot friend yourself → check on `SendRequest` POST
- Cannot send duplicate pending request → check before creating
- Cannot friend an existing friend → check before creating

**Invite validation (#044 — verify):**

- Cannot invite yourself
- Cannot join your own game (already in #017)
- Cannot create duplicate pending invite to the same person
- Cannot accept an expired invite

**Game validation:**

- Only participants can make moves, offer draws, resign (already in place — verify)
- Email confirmation required for creating/joining games (already in place — verify)

Add validation summary and field-level error messages to all affected forms.

## Acceptance criteria

- [ ] Username validation: 3–20 chars, alphanumeric + underscore, unique
- [ ] All friend request guard rules are enforced with error messages
- [ ] All invite guard rules are enforced
- [ ] Client-side and server-side validation in sync
- [ ] Error messages are user-friendly and specific
- [ ] Validation errors are displayed near the relevant form field
