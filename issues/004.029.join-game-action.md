Implement the join-game action so another player can claim an open game and the game begins.

## What to build

Add to `LobbyController` (or `GamesController`):

- `Join` POST action — takes a `gameId`
- Validation:
  - User must be authenticated with confirmed email
  - User cannot join their own game
  - Game must have `Status == WaitingForOpponent` and not be expired
- Assign the joining user as the missing color (opposite of the creator's color):
  - If creator chose White → joiner becomes Black
  - If creator chose Black → joiner becomes White
  - If creator chose Random → joiner takes the unassigned color
- Update game: `Status = InProgress`, set the appropriate player ID, set `LastMoveAt = DateTime.UtcNow`, `IsOpenInvite = false`
- Save changes and redirect to `/games/{id}`

Use optimistic concurrency checking (`RowVersion`) on save.

## Acceptance criteria

- [ ] Authenticated, confirmed user can join an open game
- [ ] User cannot join their own game (error message displayed)
- [ ] User cannot join an expired or already-started game
- [ ] Joiner is assigned the opposite color of the creator
- [ ] Game status transitions to `InProgress`
- [ ] `IsOpenInvite` is set to false
- [ ] Redirects to game page after successful join
- [ ] Concurrency conflict is handled gracefully if two users join simultaneously
