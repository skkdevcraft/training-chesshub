When a move is made, push the updated board state and move data to both players via SignalR so the opponent's board updates automatically.

## What to build

In the `MakeMove` POST handler (#022/#025):

- After successfully persisting a move, use `IHubContext<GameHub>` to broadcast a `MoveMade` event to the group `game-{gameId}`
- The event payload should include: new `fen`, `san` (the SAN of the move just made), `moveNumber`, `from`, `to`, `isCheck`, `isCheckmate` (if applicable)

In `GameHub`:

- No new server method needed — this is a server-to-client push via `IHubContext`

On the client (game page JavaScript):

- Listen for `MoveMade` events from the hub connection
- When received: update the board with the new FEN, append the move to the move history list, auto-scroll, clear any check/checkmate indicators from the previous state
- The board should remain interactive for the player whose turn it now is

The player who made the move also receives the event — their board is already updated via the POST response, so the SignalR event can be used to confirm/keep in sync.

## Acceptance criteria

- [ ] `MoveMade` event is broadcast to the game group after each move
- [ ] Opponent's board updates with the new position without page refresh
- [ ] Move history list updates on both clients
- [ ] Turn indicator updates (board enables for the player who is now on turn)
- [ ] Player who made the move does not see a double-update (handled gracefully)
