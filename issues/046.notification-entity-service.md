Create the `Notification` entity with its type enum and service, then generate the migration.

## What to build

In `ChessHub.Domain`:

- Create `NotificationType` enum: `YourTurn`, `FriendRequest`, `GameInvite`, `GameEnded`, `AchievementUnlocked`, `System`
- Create `Notification` entity:
  - `Id` (Guid)
  - `UserId` (string, FK to User)
  - `Type` (NotificationType)
  - `Message` (string — human-readable message)
  - `IsRead` (bool, default false)
  - `CreatedAt` (DateTime, default DateTime.UtcNow)
  - Navigation property: `User`

In `ChessHub.Application`:

- Create `INotificationService` interface:
  - `Task CreateAsync(string userId, NotificationType type, string message)`
  - `Task<List<Notification>> GetForUserAsync(string userId)`
  - `Task<int> GetUnreadCountAsync(string userId)`
  - `Task MarkAsReadAsync(Guid notificationId, string userId)`
  - `Task MarkAllAsReadAsync(string userId)`
- Implement `NotificationService` in `Application` (can access DbContext since `Application` references `Infrastructure` → `Data` — adjust if needed; the service may need to live in `Data` or a shared layer if dependency direction prevents direct DbContext access)

In `ChessHub.Data`:

- Add `DbSet<Notification>` to `AppDbContext`
- Run migration

## Acceptance criteria

- [ ] `NotificationType` enum with all 6 values
- [ ] `Notification` entity with all properties
- [ ] `INotificationService` interface with CRUD methods
- [ ] `NotificationService` implementation
- [ ] Service registered in DI
- [ ] Migration creates `Notifications` table
