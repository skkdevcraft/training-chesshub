Create the server endpoint that receives a move, persists it to the database, and updates the game's FEN.

## What to build

Add to `GamesController`:

- `MakeMove` POST action at `/games/{id}/move`
- Authorization: only game participants can make moves, and only on their turn
- Accept `from`, `to`, `promotion` (optional) from the client
- Compute the new FEN after the move — at this stage, use a simple approach (manually update FEN string, or use a basic helper)
- **Important**: full rule validation is deferred to M6; in this milestone, accept the move if it seems plausible (piece exists on `from` square)
- Create a `Move` entity:
  - `GameId`, `MoveNumber` (next sequential number for this game), `FromSquare`, `ToSquare`, `PromotionPiece`, `SAN` (generate from from/to), `FEN` (new position), `Timestamp = DateTime.UtcNow`
- Update `Game.CurrentFEN` to the new FEN and `Game.LastMoveAt`
- Handle concurrency with `RowVersion`
- Return JSON response with success indicator and updated FEN

Use a `GameService` in `ChessHub.Application` to keep the controller thin.

## Acceptance criteria

- [ ] `POST /games/{id}/move` accepts `from` + `to` + optional `promotion`
- [ ] Only game participants can make moves (authorization check)
- [ ] Only the player whose turn it is can move (turn check via FEN)
- [ ] Move is persisted to the `Moves` table with sequential `MoveNumber`
- [ ] `Game.CurrentFEN` is updated after the move
- [ ] `Game.LastMoveAt` is updated
- [ ] Returns JSON `{ success: true, fen: "..." }` on success
- [ ] Returns error JSON on unauthorized or out-of-turn attempt
