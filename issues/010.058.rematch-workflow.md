After a game ends, allow either player to offer a rematch. If accepted, create a new game with swapped colors. Broadcast via SignalR.

## What to build

Add to `GamesController`:

- `OfferRematch(int gameId)` POST
  - Verify the current user is a participant in the completed game
  - Verify the game has ended (`Status` is WhiteWon, BlackWon, or Draw)
  - Create a rematch offer state — can be tracked with a `RematchOffered` flag on the Game, or create a separate lightweight entity, or use an in-memory/simple db field
  - Broadcast `RematchOffered` to the game group via GameHub
  - The offer includes the offering player's username

- `AcceptRematch(int gameId)` POST
  - Verify the current user is the other participant
  - Create a new game:
    - Swap colors: if original game had player A as White and B as Black, new game has A as Black and B as White
    - `Status = InProgress`
    - `IsOpenInvite = false`
  - Broadcast `RematchAccepted` to the group
  - Redirect to the new game

- `DeclineRematch(int gameId)` POST
  - Broadcast `RematchDeclined` to the group
  - Clear the rematch offer state

On the game page client:

- Listen for `RematchOffered` — show "Opponent offers a rematch" with Accept/Decline buttons
- Listen for `RematchAccepted` — redirect to the new game page
- Listen for `RematchDeclined` — show "Rematch was declined" message, hide offer UI

Display a "Offer Rematch" button on the game page after the game ends.

## Acceptance criteria

- [ ] "Offer Rematch" button appears after game ends
- [ ] Rematch offer is broadcast to opponent via SignalR
- [ ] Accepting creates a new game with swapped colors
- [ ] Declining clears the offer and notifies the offering player
- [ ] Only the other participant (not the offerer) can accept/decline
- [ ] New game redirects both players (via SignalR or client-side navigation)
