Create the `Move` entity to persist each chess move with its metadata, and generate the migration.

## What to build

In `ChessHub.Domain`:

- Create `Move` entity:
  - `Id` (Guid or long)
  - `GameId` (FK to Game)
  - `MoveNumber` (int — the move number within the game, starting at 1)
  - `FromSquare` (string, e.g., "e2")
  - `ToSquare` (string, e.g., "e4")
  - `PromotionPiece` (string, nullable — "q", "r", "b", "n" if a pawn promotes)
  - `SAN` (string — Standard Algebraic Notation, e.g., "e4", "Nf3", "exd5")
  - `FEN` (string — the FEN position AFTER this move is made)
  - `Timestamp` (DateTime)
- Navigation property: `Game`

In `ChessHub.Data`:

- Add `DbSet<Move>` to `AppDbContext`
- Configure the relationship to `Game` (many moves per game)
- Add an index on `(GameId, MoveNumber)` for efficient querying
- Run migration

## Acceptance criteria

- [ ] `Move` entity with all fields exists
- [ ] `MoveNumber` starts at 1 and increments per game
- [ ] `SAN` stores standard algebraic notation
- [ ] `FEN` stores the position after the move
- [ ] Many-to-one relationship with `Game` configured
- [ ] Index on `(GameId, MoveNumber)` created
- [ ] Migration runs successfully
