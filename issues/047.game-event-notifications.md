Wire the notification service into game events so users are notified when it's their turn or a game ends.

## What to build

In the `MakeMove` POST handler (#022/#025):

- After successfully persisting a move, call `INotificationService.CreateAsync()` for the **opponent** with:
  - `Type = NotificationType.YourTurn`
  - `Message = "It's your turn in a game against {opponentUsername}."`
  - Include a link to the game

In the game-end logic (#027/#028):

- After a game ends (checkmate, draw, resignation, etc.), create notifications for **both players** with:
  - `Type = NotificationType.GameEnded`
  - `Message = "Game ended: {result}. Against {opponentUsername}."`

Also broadcast notification count changes via SignalR so the navbar bell updates in real time (the bell itself is built in #036). For now, just create the notifications in the database.

## Acceptance criteria

- [ ] `YourTurn` notification is created for the opponent after each move
- [ ] `GameEnded` notification is created for both players when a game ends
- [ ] Notification message includes opponent username and game link
- [ ] Notifications persist to the database
- [ ] Duplicate notifications are avoided (check before creating)
