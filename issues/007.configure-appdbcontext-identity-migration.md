Configure `AppDbContext` to use Identity with the custom `User` entity, and generate the Identity migration.

## What to build

In `ChessHub.Data`:

- Change `AppDbContext` to inherit from `IdentityDbContext<User>` instead of plain `DbContext`
- In `OnModelCreating`, call `base.OnModelCreating(modelBuilder)` so Identity tables are configured
- Add any necessary Identity role/store configuration

In `ChessHub.Web/Program.cs`:

- Register Identity services: `AddIdentity<User, IdentityRole>()` or `AddIdentityCore` + `AddEntityFrameworkStores<AppDbContext>()`
- Configure cookie settings (login path, access denied path, etc.)
- Add `app.UseAuthentication()` and `app.UseAuthorization()` in the middleware pipeline (if not already there from #003)

Run a new migration:

```bash
dotnet ef migrations add Identity --project ChessHub.Data --startup-project ChessHub.Web
dotnet ef database update
```

Verify the Identity tables exist in PostgreSQL (AspNetUsers, AspNetRoles, AspNetUserClaims, etc.).

## Acceptance criteria

- [ ] `AppDbContext` inherits from `IdentityDbContext<User>`
- [ ] `base.OnModelCreating(modelBuilder)` is called
- [ ] Identity services are registered in `Program.cs`
- [ ] Auth middleware (`UseAuthentication` / `UseAuthorization`) is in the pipeline
- [ ] Migration `Identity` creates all standard Identity tables
- [ ] `AspNetUsers` table includes the custom columns (`EloRating`, `JoinDate`, etc.)
