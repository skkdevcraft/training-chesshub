Create the `Game` entity with all required properties and the `GameStatus` enum, then generate the migration.

## What to build

In `ChessHub.Domain`:

- Create `GameStatus` enum: `WaitingForOpponent`, `InProgress`, `WhiteWon`, `BlackWon`, `Draw`, `Aborted`
- Create `Game` entity with properties:
  - `Id` (Guid)
  - `WhitePlayerId` (string, FK to User)
  - `BlackPlayerId` (string, FK to User, nullable — null until someone joins)
  - `CurrentFEN` (string, default starting position FEN)
  - `Status` (GameStatus, default `WaitingForOpponent`)
  - `IsOpenInvite` (bool, default true)
  - `DesiredColor` (string — "White", "Black", "Random")
  - `CreatedAt`, `UpdatedAt`, `LastMoveAt` (DateTime)
  - `ExpiresAt` (DateTime — set to `CreatedAt + 72 hours` for open games)
  - `RowVersion` (byte[] — for optimistic concurrency, configured as `IsRowVersion()`)
- Navigation properties: `WhitePlayer` (User), `BlackPlayer` (User)

In `ChessHub.Data`:

- Add `DbSet<Game>` to `AppDbContext`
- Configure relationships (two FKs to User) and `RowVersion`
- Run migration

## Acceptance criteria

- [ ] `GameStatus` enum with all 6 values
- [ ] `Game` entity with all properties including `RowVersion`
- [ ] Two foreign key relationships to `User` (WhitePlayer, BlackPlayer) with BlackPlayer nullable
- [ ] `RowVersion` is configured as concurrency token
- [ ] Migration creates the `Games` table correctly
- [ ] Default `CurrentFEN` is the chess starting position
